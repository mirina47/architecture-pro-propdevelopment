# Список требований
## Требования к безопасности
- Взаимодействие между системами должно осуществляться по защищённым каналам связи (TLS 1.2 и выше).
- Биометрические данные (распознавание лиц) и данные о транспортных средствах (госномера) хранятся и обрабатываются на стороне партнёра с соблюдением требований законодательства РФ о персональных данных.
- Передача персональных и чувствительных данных должна быть минимизирована и обезличена, когда это возможно (токены, идентификаторы, хеши).
- Все обращения к внешним API подлежат журналированию с возможностью последующего аудита.
- Должны применяться механизмы ограничения частоты запросов (rate limiting) и защиты от некорректных или повторных запросов.

## Протоколы аутентификации и авторизации
- Для аутентификации между smarthome-integration-api и внешней платформой партнёра используется протокол OAuth 2.0.
- Для передачи прав доступа применяются JWT-токены с ограниченным временем жизни.
- Дополнительно на транспортном уровне может использоваться mutual TLS (mTLS).
- Авторизация реализуется на основе ролевой модели (RBAC) с разделением прав.
- Пользовательская аутентификация и авторизация собственников выполняется только внутри систем PropDevelopment.

## Организация взаимодействия между системами предприятия и внешней платформой
- Собственник проходит аутентификацию и авторизацию в мобильном приложении PropDevelopment.
- Мобильное приложение взаимодействует с приложением tenant-core-app. tenant-core-app взаимодействует с интеграционным слоем smarthome-integration-api по REST API и WebSocket.
- Интеграционный слой smarthome-integration-api:
    - Инкапсулирует логику работы с внешними API.
    - Адаптирует форматы данных партнёров.
    - Обеспечивает единые политики безопасности.
- smarthome-integration-api взаимодействует с внешними системами «Интеллектуальный домофон» и «Интеллектуальный шлагбаум» по REST API.
